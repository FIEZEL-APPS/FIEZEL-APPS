## 1. OWNER AMENDMENT RECORD (2026-08-27) — G5 replaced

### 1.1 The amendment

> **OWNER decision, 2026-08-27:** PAW as shipped is too plain. A curated outfit/accessory system is now **REQUIRED**. Examples named by the OWNER: backpack (ransel), hat (topi), flower (bunga), "and so on".

This is a **binding OWNER amendment**, recorded here with the same authority as the m025-128 mascot adoption and the 2026-08-27 chest-only-glyph revision (08 "OWNER revision"). It **supersedes** the blanket constraint:

- ~~**G5** — "No new accessories beyond the sanctioned `fz-acc` set… No hats, books, or seasonal props."~~ (`FIEZEL-PAW-REDESIGN-SPECIFICATION.md` global table; `audit/02` §5.5, checklist A5)
- ~~BRAND-GUIDE §1 identity lock, the words "no **hats**"~~ (the rest of that lock — no third eye, **no glasses**, no claim-bearing speech bubbles — **stands unchanged**; glasses were not named by the OWNER and remain banned because they alter the eyes, an identity organ).

Documented as an **amendment, not a violation**: earlier same-day documents (08 §3, 17) that treat "new accessory" as an automatic defect are correct *for their date of authorship* and are flagged for a revision pass in §9.

### 1.2 G5′ — the replacement governance rule (normative)

**G5′ (2026-08-27):** PAW may wear items **only from the curated OUTFIT REGISTRY (§5)**. The registry is:

1. **Closed and versioned** — an item exists only if it has a registry row here (ID `OF-xx`) with full geometry, anchor, context, and tier data. "And so on" in the OWNER's wording is licensed **only** through new registry rows, never through ad-hoc art.
2. **OWNER-gated** — adding, retiring, or visually changing a registry item requires an explicit OWNER decision line, like this amendment itself.
3. **Never random, never user-generated** — outfit selection is a deterministic context function (§6.1). No randomizer, no dress-up UI, no user wardrobe. (This is also the core anti-Duolingo mechanic difference, §8.)
4. **Not a reward economy** — outfits are context dressing. They are never bought, earned, unlocked, or monetized (G7 "no game-mechanics changes" already forbids this; restated here because Duolingo's outfit system was exactly a gem-priced shop, §8).
5. **The emotive `fz-acc` set is untouched** — headphones, notes, dots, bulb, stars, zzz, tear, hearts, sweat remain the *ephemeral emotive* vocabulary with their existing rules. Outfits are a **separate, worn** layer (`fz-outfit-*`, §4). One interaction rule: an `fz-acc` item that occupies the head slot (headphones) counts as a HEAD-slot occupant for the §6.2 concurrency cap.
6. **Everything else survives** — G1 palette (§3), G2 grammar (§3), G4 rotation-free body, G6 tail ring, G9 reduced motion, chest-only paw glyph (hands stay plain), pose legality (08). An outfit that cannot satisfy these does not enter the registry.

## 2. Design language

Accessories must look like they were **drawn by the same hand as PAW**:

- **Grammar (G2):** every item decomposes into circles, capsules (round-capped strokes / rx=½-height rects), and triangles. Sheet inventory: cap = clipped circle dome + capsule brim + circle button; toga = diamond (two triangles) + capsule band + circle-tipped capsule tassel; flower = 5 petal circles + center circle; scarf = capsules + capsule fringe; backpack = rounded-capsule bag + capsule straps + circle pockets; beret = ellipse + capsule rim + capsule stem; pencil = capsule + 2 triangles + capsule eraser; nightcap = triangle cone + capsule band + circle pompom.
- **No outlines, no gradients, no textures** — flat fills only, same as the body.
- **Scale discipline:** minimum feature stroke/width 5px in rig units (matches the facial-stroke floor), so items survive the size ladder the same way the face does.
- **Tone:** items must read *companion/learning*, never costume/cosplay. No full-body suits, no capes, no masks, no branded merch look — PAW wears *an* item, PAW never *becomes* something else (same-body doctrine, 07 "never new drawings"; also anti-copy §8).

All 8 starter items use **only** sanctioned hexes: maroon `#8C2233` (cap, beret, straps, pockets, nightcap cone), gold `#D8B36B` (bag, pencil body, buttons, tassel, pompom, stem), soft red `#D9536A` (scarf — its first on-body use, sanctioned in G1), blush `#F0A0AC` (petals, eraser), cream `#FFF4DA` (pencil tip, nightcap band), ink `#33201F` (mortarboard, graphite). Verified by palette scan of `outfit-sheet.svg` (only G1 hexes + `#fff` highlights, `#000` shadows, and sheet chrome `#FFF9EE`/`#241A11`/`#6E5E47` outside the character groups).

## 4. Attachment contract — `fz-outfit-*` anchor groups

Three new anchor groups, additive to the `fz-*` class contract (G12). Anchors carry **no transform of their own**; items are static geometry in anchor-local (= rig) coordinates and track motion purely by **transform inheritance** — zero new animation nodes required for tracking.

### 4.1 Slots and z-order (insertion points in the canonical rig)

| Anchor | Parent / insertion point | Inherits (so items track…) | Occludes / occluded by |
|---|---|---|---|
| `fz-outfit-back` | inside `fz-all`, **after `fz-tail`, before the body rect** | P1 `fz-all` translate + ground-anchored squash `scale(sx,sy)` about (160,284) → bag squashes/jumps with the body automatically | behind body/head/arms; in front of tail |
| `fz-outfit-front` | inside `fz-body`, **after `fz-head`, before the arms** | P1 chain (same as body mass) | in front of torso, chin-adjacent band allowed below y=168; arms drawn later naturally overlap (straps sit under arms — correct physicality) |
| `fz-outfit-head` | inside `fz-head`, **after the ear groups + skull disc (r=88), before `fz-face`** | P1 chain **+ P2 head translate (tx −6…6, ty −4…4)** → hats/flowers lean with every head lean, no code | in front of skull + ear bases (headphones precedent, 08 §1.8); behind all face features |

### 4.2 Pivot math (normative)

- **Head-item placement:** the skull cap is circle C((160,106), r=88). An item resting on the crown at chosen x is placed at y(x) = 106 − √(88² − (x−160)²) + inset (inset 2–8px so the item "grips"). Worked examples: cap dome center (160,68) clipped at y≤66; beret disc (140,34) rot −8°; toga board center (160,40).
- **Ear-adjacent items** (flower, pencil): NEVER parented to `fz-ear-l/r` (ears rotate ±14–18° and would fling a rigid item). Instead anchor to `fz-outfit-head` at a point within **≤14px of the ear pivot** ((108,52) L / (212,52) R), so a full 18° ear swing displaces the adjacent ear edge by ≤ 14·sin18° ≈ 4.3px and the "tucked" contact never visibly breaks. Verified: flower center (222,60) → 12.8px from R pivot; pencil visual center (~103,52) → ~5px from L pivot.
- **Own micro-motion (optional, decorative):** an item may own at most ONE rotating subgroup around a documented pivot, transform/opacity only (G3), amplitude ≤8°, riding existing JS timers (no new loops): toga tassel ±6° @ (160,40); nightcap pompom+tip ±5° @ (218,20); scarf drape ±3° @ (202,182). **Reduced motion: all outfit micro-motion is OFF; the item itself stays visible and static** (outfits are static-safe by construction — they are static geometry).
- **Whole-body legality is untouched:** items never rotate `fz-all`/`fz-body`/`fz-head`, never mirror, never add transforms to identity organs (G4).

### 4.3 Keep-out zones (hard; any hit = invalid export)

No outfit ink may overlap, at any allowed pose/tier:

1. **Face organs:** eye discs (126,98,r16)/(194,98,r16) + gaze range ±7/±5, brow paths (y 56–80, x 108–212), nose triangle, mouth region (x 140–180, y 140–166), muzzle ellipse (160,140,36×25), blush circles (102,126,r11)/(218,126,r11).
2. **Chest emblem:** paw-glyph ink bbox at s=1.75 → x 146–174, y 209–241, **+6px margin** (straps at x 110–127 / 193–210 clear it; scarf band bottom y=192 clears patch top y=198).
3. **Tail ring:** disc r15 at the tip bone +4px margin (scarf drape verified clear).
4. **Ear inner triangles** may be overlapped only by the two sanctioned ear-tuck items (flower, pencil) and only ≤ 30% of the inner-triangle area.

## 6. System rules

### 6.1 Selection is a context function (never random)

`outfitFor(state, surface, tier, scenePhase) → OF-xx | none`, resolved from the §5 context columns at mount/state-change time, deterministic for identical inputs. Precedence when several match: milestone items (OF-05) > state-bound items (OF-08) > session-context items (OF-01/04/07) > ambient items (OF-02/03/06). Default is **none** — an undressed PAW remains the canonical PAW; outfits are seasoning, not the dish ("a rarer PAW is a stronger PAW", 12 §4, applies to wardrobe too).

### 6.2 Concurrency cap: max 1, hard max 2

- **Default: exactly ONE outfit item.** Every §5 context row resolves to a single item.
- **Hard max TWO**, only as sanctioned combos, only at Large/Full (marketing, completion overlay, share-resolution art): `OF-01 + OF-02` (ready-for-lessons), `OF-01 + OF-03` (welcome-back journey). Never two HEAD-slot items; `fz-headphones` counts as a HEAD occupant (so listening state never combines with any hat — 08 §1.8 stays intact).
- `fz-acc` emotive overlays (dots, stars, zzz…) stack per their existing rules and do NOT count against the cap — except the headphone rule above.

### 6.3 Never obscure identity organs

Keep-out zones §4.3 enforced at every pose × item × tier combination in the item's allowed matrix. The identity checklist (audit/02 §6 A1–A4) must pass **with the outfit on**: face fully readable, chest emblem fully visible, tail ring visible, silhouette still "geometric yellow cat wearing X" — never "new character".

### 6.4 Reduced motion / static safety (G9)

Outfits are static geometry — they render identically with all motion off. Item micro-motion (§4.2) is decorative-only and disabled under any of the 3 reduced-motion layers. No outfit may *depend* on motion to read (verified: the proof sheet is static).

### 6.5 Small-size drop ladder

Per-item survival is in §5; the global ladder:

| Tier | Rule |
|---|---|
| Full / Large (120px+) | any registry item, combos allowed (Large+ only) |
| Medium (88px dock) | single item only; drop fine parts (tassel/button/pompom/fringe per §5) if the part renders <2px |
| Small (30–58px head crop) | head-slot items only, simplified forms per §5; body/front items drop (out of crop or <1px features) |
| Tiny (22–28px) | **ALL outfits drop.** The identity floor is naked PAW — same doctrine as the expression small-size rules (07 SS) |

Dropping is silent and per-surface; an item never "pops" mid-animation — tier is fixed at mount.

### 6.6 Tone guards

No claim-bearing props (a worn item never carries text/logos/UI), no guilt costumes (no crying/sad-themed items), no seasonal-religious items without a separate OWNER decision, honest-claims rules untouched (BRAND-GUIDE §6). The toga appears only on real level-up/completion events the app already emits (G7).

2. Palette scan — G1 hexes only (plus signed-off §3.2 extension if/when approved); zero pixels within ΔE<15 of `#58CC02`/`#89E219`.
3. Keep-out overlap test (§4.3) at every allowed pose × tier.
4. Same-character test with item ON at 88px and 512px.
5. Chest-only glyph gate: 1 emblem instance, 0 pad instances (15 §8 hash gate).
6. Tail-ring present (G6).
7. Static render with all motion disabled reads identically (§6.4).
8. 16 §5 same-test rubric rows 1–3, 7, 8 re-run with the outfit on (see §8).

## 8. Anti-Duolingo differentiation note (binding, extends 16 §3)

Duo demonstrably has an outfit system, so this feature needs explicit distance. Duolingo's outfits were a **gem-priced cosmetic shop** — Formal Attire 400 gems, "Luxury/Champagne Tracksuit" 600, "Super Duolingo" superhero cape+mask 1000, plus a seasonal Dragon suit — that dressed Duo in the lesson interstitials until the feature was removed over 2022 ([Duolingo Wiki — Outfits](https://duolingo.fandom.com/wiki/Outfits); [duoplanet — the Duolingo shop](https://duoplanet.com/we-need-to-talk-about-the-duolingo-shop/)); TV Tropes catalogues it as a "Virtual Paper Doll" mechanic ([TV Tropes — Duolingo](https://tvtropes.org/pmwiki/pmwiki.php/Characters/Duolingo)), and Duo also recolors/costumes by subscription tier (Super/MAX) ([Mascotpedia — Duo](https://mascots.fandom.com/wiki/Duo)).

PAW's system is different **in mechanics and in style**, and must stay so:

| Axis | Duo | PAW (this spec) |
|---|---|---|
| Acquisition | purchased with gems / tied to subscription tiers | **never acquired** — no shop, no unlocks, no currency, no wardrobe UI (G5′-3/4, G7) |
| Selection | user equips ("WEAR") | deterministic context function; the learner never dresses PAW (§6.1) |
| Form | full costumes: tuxedo+monocle, tracksuit, cape+mask | single small worn items, max 1–2, same-body always; full costumes/transformations banned (§2, 16 §3.1-3) |
| Style | multi-color costume art | closed 8-hex palette, circles/capsules/triangles, flat fills (§2–3) |
| Persona | costume as monetized flair + meme fuel | outfit as *learning-context* signal (backpack = lesson journey, pencil = drill, toga = real milestone, nightcap = healthy rest — guilt-free per 16 §3.1-4) |

**Blocklist additions (any hit = QA failure):** no tuxedo/formal suit, no monocle, no tracksuit/headband combo, no superhero cape or mask, no dragon/holiday costume, no subscription-tier recolor — these are Duo's specific catalogue ([Duolingo Wiki — Outfits](https://duolingo.fandom.com/wiki/Outfits)). Item-shape overlap with generic reality (a cap is a cap) is acceptable; overlap with Duo's *specific catalogue, acquisition mechanics, or composition* is not. The 16 §5 same-test rubric applies to every outfit asset, with rubric row 3 (pose lineup) extended to a **wardrobe lineup**: place the dressed PAW beside Duo outfit screenshots — no item may match in garment type + styling + context simultaneously.
